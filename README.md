# ParserBank

Телеграм-бот к интернет-банку ВТБ: присылает поступления, показывает счета
и историю, умеет переводить деньги себе в другой банк по СБП.

| Команда | Что делает |
|---|---|
| `/balance` | остатки по счетам и картам |
| `/last` | история операций, листается кнопками |
| `/backfill [месяцев]` | догрузить историю за прошлые месяцы |
| `/pay 5000` | перевод себе в другой банк, подтверждается кнопкой |
| `/status` | вход, зеркало, аптайм, возраст сессии |
| `/mirrors` | какие зеркала банка живы |
| `/login` | вернуть окно браузера на страницу банка |
| `/inspect` | снять селекторы текущей страницы (для `transfer.json`) |

Плюс уведомление в личку при каждом зачислении. Всё продублировано
инлайн-кнопками.

## Зачем

Чтобы **не ставить корневой сертификат Минцифры на телефон**.

ВТБ под санкциями: приложения нет в сторах, а основной домен `online.vtb.ru`
отдаёт сертификат, выписанный корнем Минцифры, — его нет в доверенных ни у
одной ОС. Чтобы пользоваться банком с телефона, предлагают этот корень
поставить.

Дело не в том, кто его выпустил, а в том, что такое корневой сертификат: он
подтверждает подлинность **любого** сайта, а не одного банка. Установив его,
вы соглашаетесь, что его владелец может выписать валидный сертификат на почту,
мессенджер, что угодно — и телефон поверит. Доверие там общесистемное, выдать
его одному приложению нельзя.

Поэтому банк живёт в отдельном профиле браузера на одной машине, а телефон
разговаривает только с Telegram. Сертификат не нужен и на этой машине: зеркала
работают на обычном Let's Encrypt.

| Хост | Издатель | Проверка цепочки |
|---|---|---|
| `online.sbpvtb.ru` | Let's Encrypt YE1 | `0 (ok)` |
| `sso-ib.sbpvtb.ru` | Let's Encrypt YE1 | `0 (ok)` |
| `online.vtb.ru` | Минцифры РФ | `19 (self-signed in chain)` |

Если однажды понадобится — его кладут рядом с проектом и скармливают одному
процессу, `NODE_EXTRA_CA_CERTS=./russian_trusted_root_ca.pem go run ./cmd/bot`,
а не в системное хранилище.

Второй повод: уведомления о зачислениях иначе взять неоткуда — SMS платные,
пуши приходят в приложение, которого нет.

## Как это работает

Кабинет — SPA, парсить в нём нечего: балансы приезжают JSON'ом в ручки
`/services/…`. Обычный HTTP-клиент туда не пустят — на входе SSO с OTP,
SmartCaptcha и антифрод F6, снимающий отпечаток устройства.

```
Chromium с постоянным профилем (Playwright)   профиль хранит куки и отпечаток
        └─► APIRequestContext ──► /services/… ──► JSON
                └─► поллер ──► SQLite ──► Telegram
```

Запросы идут через `APIRequestContext` браузера, а не `net/http`: так они
наследуют куки живого профиля и тот же TLS-стек, что и сама страница.

## Установка

Нужны Go 1.24+, Node.js и установленный Google Chrome.

```bash
cp .env.example .env
./scripts/install-driver.sh
make doctor
```

В `.env` обязательны `TG_BOT_TOKEN` ([@BotFather](https://t.me/BotFather)) и
`TG_OWNER_ID` ([@userinfobot](https://t.me/userinfobot)). `make doctor` покажет
чеклист окружения, не заходя в банк.

Драйвер ставится скриптом, потому что playwright-go качает его с выключенного
Microsoft'ом CDN; тот же пакет берётся из npm. Браузер не качается вообще —
используется системный Chrome (`BROWSER_CHANNEL=chrome`), для антифрода это
даже лучше.

<details>
<summary>Если Chrome не запускается на macOS</summary>

«Приложение заблокировано при попытке внести изменения» лечится в
**Системные настройки → Конфиденциальность и безопасность → Управление
приложениями** — разрешите тому, откуда запускаете. Или запускайте из

### Discovery — найти ручки банка

API нигде не документировано и меняется без предупреждения, поэтому адреса
снимаются с живого сайта один раз:

```bash
make record
```

Войдите в кабинет, откройте счета, откройте и пролистайте историю, дождитесь
`✓ нашёл и счета, и операции` и нажмите `Ctrl+C`. `endpoints.json` соберётся
сам: анализатор находит массивы по форме данных (дата + сумма + валюта —
операции; остаток без дат — счета) и подставляет пути к полям. `make map`
перепроходит разбор по снятым дампам, `make report` только показывает отчёт.

Токен на диск не попадает — записывается лишь то, из какого ключа хранилища
фронт его берёт. А вот дампы содержат **ваши финансовые данные**, поэтому
`data/` целиком в `.gitignore`.

Схема лежит в JSON намеренно: когда банк поменяет API, чинится правкой одного
файла. Формат полей с комментариями — в
[endpoints.example.json](endpoints.example.json).

### Запуск

```bash
make bot
```

Первый проход сохраняет историю молча, иначе прилетело бы уведомление о каждой
старой операции. Дальше — только новое.

## Вход и сессия

Токен ВТБ лежит в `sessionStorage` и умирает вместе с окном браузера. Перенос
на диск был написан и **проверен — не работает**: сервер такой токен не
принимает. Значит:

- вход живёт ровно столько, сколько процесс; любой перезапуск — вход руками;
- логин делает человек в видимом окне, бот сам его замечает (проверяет
  страницу раз в 3 секунды) и пишет «✅ Вижу вход»;
- `systemd` с `Restart=always` тут не помогает: бот поднимется, но без входа.

**Сессию держит опрос.** ВТБ разлогинивает после 3–5 минут бездействия, а
единственная активность, которую он видит, — запросы бота. При
`POLL_INTERVAL=60s` таймаут не наступает никогда; интервал больше `2m`
отвергается на старте — это не вежливость, а условие работоспособности.

Пароль нигде не хранится и не вводится программно: вход всё равно
подтверждается кодом, так что автоматизировать его невозможно, а хранение
добавило бы риск. Сколько сессия держится на самом деле — покажет `/status`.

Окно браузера руками не закрывайте: бот заметит и остановится.

## Перевод себе (`/pay`)

Последнее нажатие всегда за человеком:

1. `/pay 5000` или кнопка в меню — бот заполняет форму и жмёт «Продолжить».
   Деньги на месте, банк показывает экран сверки;
2. бот присылает запрос с кнопками **✅ Подтвердить** / **✖️ Отменить**;
3. по нажатию жмёт «Перевести»; если банк спросит код из SMS — попросит его.

Подтверждение в чате стоит там, где обычно стоял бы код: перевод себе ВТБ
проводит **без SMS**, и других точек контроля не остаётся. Дать его текстом
нельзя, только кнопкой.

**Защита:** получатель зафиксирован в `.env` (из чата приходит только сумма),
есть лимит суммы, а по умолчанию включён черновой режим `TRANSFER_ARMED=false`
— форма заполняется, но не отправляется. Без нажатия перевод истекает сам.
Отмена честно называет состояние: до финальной кнопки «деньги на месте», после
— «нажатие уже состоялось, проверьте историю».

### Настройка

1. `TRANSFER_PHONE`, `TRANSFER_BANK`, `TRANSFER_MAX_AMOUNT` в `.env`;
2. `transfer.example.json` → `transfer.json`, шаги под свою форму. Селекторы
   снимаются командой `/inspect` прямо на нужном экране;
3. гоняйте `/pay` в черновом режиме, пока форма не заполнится правильно;
4. только потом `TRANSFER_ARMED=true`. Без описанных `submit` и `confirm` бот
   вооружаться откажется.

Шаги `otp_field`/`otp_confirm` нужны, только если банк просит код после
финальной кнопки.

<details>
<summary>Если шаг не находит элемент</summary>

Первое подозрение — **написание атрибута**: Playwright знает только
`data-testid`, а ВТБ подписывает элементы `data-test-id`. Достаточно написать
`"testid": "sum_input"` — код проверяет все распространённые написания и `id`,
а `/inspect` показывает, каким подписан конкретный элемент.

Второе — кастомное поле: настоящий `<input>` скрыт, поверх нарисован `div`.
Такие помечены `[скрыто]`; шаг `fill` пробует три способа подряд и сверяет
результат числом, а не строкой (`5 000,00 ₽` = `5000`).

К ошибке шага прикладывается ответ на главный вопрос: элемента нет вовсе или
он есть (и тогда дело в ожидании, а не в поиске).
</details>

### Риск

**Автоматизированный исходящий перевод — ровно тот паттерн, который антифрод
ловит первым делом:** форму, заполненную скриптом, видно по таймингам и
отсутствию движений мыши. Реальный исход при регулярном использовании —
блокировка входа.

Штатная альтернатива без риска: в приложении ВТБ есть регулярный автоперевод
по СБП себе в другой банк. Если нужна фиксированная сумма по расписанию —
используйте его.

## Зеркала

ВТБ раздаёт кабинет с пула доменов и меняет их по мере блокировок. Список
вытащен из CSP самого сайта, `BANK_HOST=auto` включает автоподбор: сначала DNS
(отсеивает мёртвые, не потревожив банк), потом проба живым браузером с паузами.

Проба именно браузером по измеренной причине: edge банка отдаёт
`302 Security Redirect` не-браузерным клиентам через несколько запросов и
дальше рвёт соединение — проверка через `http.Client` сломала бы ровно то, что
чинит.

Куки привязаны к домену: после переезда на другое зеркало нужен новый вход.

## Локально и на VPS

`RUNTIME=local` — макбук, окно видно, вход руками. `RUNTIME=vps` — сервер;
кроме дефолтов включает экономию памяти в Chromium (один рендерер, без
расширений и фоновых сервисов). Отпечаток браузера при этом не трогается:
подменять user-agent ради памяти дороже, чем эту память докупить.

`HEADLESS=true` антифрод замечает, поэтому на сервере правильнее headful под
виртуальным дисплеем:

```bash
sudo apt install xvfb x11vnc
xvfb-run -a --server-args="-screen 0 1440x900x24" ./bin/bot-linux
```

Для первого входа пробросьте VNC (`x11vnc -display :99 -localhost -rfbport 5900`
плюс `ssh -L 5900:localhost:5900 user@vps`) — либо залогиньтесь на макбуке и
скопируйте профиль: `rsync -a data/profile/ user@vps:/opt/parserbank/data/profile/`.

**Расход** (замер на macOS; на Linux меньше — там RSS не считает общую память
Chromium заново в каждом процессе): браузер ~1,1 ГБ, драйвер 26 МБ, сам бот
13 МБ. Берите 2 ГБ RAM — на 1 ГБ со swap OOM-killer прибьёт Chromium вместе с
сессией. Диск: профиль растёт за счёт кеша, закладывайте 10–20 ГБ.

**Про IP.** Заграничный VPS почти гарантированно даст постоянные требования
переподтвердить вход. Российский IP спокойнее.

## Риски

- Пользовательское соглашение банка, как правило, запрещает автоматизированный
  доступ. Это ваше решение и ваша ответственность.
- Антифрод может потребовать переподтверждения входа или заблокировать доступ.
- Зеркала живут недолго: когда домен отвалится, поменяйте `BANK_HOST`.

## Структура

```
cmd/bot/           основной процесс
cmd/recorder/      разовый discovery ручек банка
cmd/mapper/        повторный разбор снятых дампов
cmd/doctor/        проверка окружения без захода в банк
internal/bank/     браузер, сессия, клиент API, зеркала, перевод
internal/discover/ эвристики: какой массив — счета, какой — операции
internal/config/   конфиг из .env и окружения
internal/store/    SQLite
internal/poller/   опрос и поиск новых зачислений
internal/tg/       команды и уведомления
```
