# ParserBank

Телеграм-бот к интернет-банку ВТБ: присылает поступления, показывает счета
и историю, умеет переводить деньги себе в другой банк по СБП.

| Команда | Что делает |
|---|---|
| `/balance` | остатки по счетам и картам |
| `/last` | история операций, листается кнопками |
| `/backfill [месяцев]` | догрузить историю за прошлые месяцы |
| `/pay 5000` | перевод себе, подтверждается кнопкой |
| `/status` | вход, зеркало, аптайм, возраст сессии |
| `/mirrors` | какие зеркала банка живы |
| `/login` | вернуть окно браузера на страницу банка |
| `/inspect` | снять селекторы страницы для `transfer.json` |

## Зачем

Чтобы **не ставить корневой сертификат Минцифры на телефон**.

ВТБ под санкциями: приложения нет в сторах, а `online.vtb.ru` отдаёт
сертификат, выписанный корнем Минцифры, — его нет в доверенных ни у одной ОС.

Дело не в том, кто его выпустил, а в том, что такое корневой сертификат: он
подтверждает подлинность **любого** сайта, а не одного банка. Установив его, вы
соглашаетесь, что его владелец может выписать валидный сертификат на почту,
мессенджер, что угодно — и телефон поверит без предупреждений. Это ровно та
возможность, которая называется MITM. Речь не о намерениях: возможность
появляется, доверие общесистемное, одному приложению его не выдать, а
украденный ключ любого центра сертификации опаснее любых намерений (DigiNotar,
2011 — поддельные сертификаты на google.com).

Поэтому банк живёт в отдельном профиле браузера на одной машине, а телефон
общается только с Telegram. На самой машине сертификат тоже не нужен: зеркала
(`online.sbpvtb.ru` и другие) работают на обычном Let's Encrypt — проверено
`openssl s_client`, минцифровский корень требует только основной домен. Если
однажды понадобится, его скармливают одному процессу через
`NODE_EXTRA_CA_CERTS`, а не системному хранилищу.

Второй повод: уведомления о зачислениях иначе взять неоткуда — SMS платные,
пуши приходят в приложение, которого нет.

## Как это работает

Кабинет — SPA, парсить нечего: балансы приезжают JSON'ом в ручки
`/services/…`. Обычный HTTP-клиент туда не пустят — SSO с OTP, SmartCaptcha и
антифрод F6 с отпечатком устройства.

```
Chromium с постоянным профилем (Playwright)   профиль хранит куки и отпечаток
        └─► APIRequestContext ──► /services/… ──► JSON
                └─► поллер ──► SQLite ──► Telegram
```

Запросы идут через браузер, а не `net/http`: так они наследуют куки живого
профиля и тот же TLS-стек, что и сама страница.

## Установка

Нужны Go 1.24+, Node.js и системный Chrome.

```bash
cp .env.example .env      # обязательны TG_BOT_TOKEN и TG_OWNER_ID
./scripts/install-driver.sh
make doctor               # чеклист окружения, не заходя в банк
```

Драйвер ставится скриптом: playwright-go тянет его с выключенного Microsoft'ом
CDN, тот же пакет берётся из npm. Браузер не качается — используется системный
Chrome, для антифрода это естественнее.

**Discovery.** API нигде не документировано, адреса ручек снимаются с живого
сайта один раз: `make record`, войти в кабинет, открыть счета, пролистать
историю, дождаться `✓ нашёл и счета, и операции`, `Ctrl+C`. `endpoints.json`
соберётся сам — анализатор различает массивы по форме данных. Токен на диск не
попадает, записывается только ключ хранилища, откуда его берёт фронт. Дампы
содержат ваши финансовые данные, поэтому `data/` в `.gitignore`. Формат полей —
в [endpoints.example.json](endpoints.example.json).

Дальше `make bot`. Первый проход сохраняет историю молча, уведомления идут со
второго.

## Вход и сессия

Токен лежит в `sessionStorage` и умирает вместе с окном браузера. Перенос на
диск написан и **проверен — не работает**, сервер такой токен не принимает.
Отсюда:

- вход живёт ровно столько, сколько процесс; перезапуск — вход руками
  (`systemd` с `Restart=always` не поможет: бот поднимется без входа);
- логин делает человек в видимом окне, бот сам его замечает;
- пароль нигде не хранится: вход подтверждается кодом, автоматизировать
  невозможно.

**Сессию держит опрос.** ВТБ разлогинивает после 3–5 минут бездействия, а
активность для него — только запросы бота. При `POLL_INTERVAL=60s` таймаут не
наступает; интервал больше `2m` отвергается на старте. Окно браузера руками не
закрывайте — бот заметит и остановится.

## Перевод себе (`/pay`)

1. `/pay 5000` — бот заполняет форму и жмёт «Продолжить», банк показывает
   экран сверки, деньги на месте;
2. бот присылает запрос с кнопками **✅ Подтвердить** / **✖️ Отменить**;
3. по нажатию жмёт «Перевести».

Подтверждение кнопкой стоит там, где обычно стоял бы код: перевод себе ВТБ
проводит **без SMS**, других точек контроля не остаётся. Текстом его дать
нельзя.

Получатель зафиксирован в `.env` — из чата приходит только сумма, и она
ограничена лимитом. По умолчанию `TRANSFER_ARMED=false`: форма заполняется, но
не отправляется. Настройка: скопировать `transfer.example.json` в
`transfer.json`, снять селекторы через `/inspect`, выверить в черновом режиме и
только потом вооружаться.

**Риск.** Автоматизированный исходящий перевод — ровно тот паттерн, который
антифрод ловит первым: заполненную скриптом форму видно по таймингам и
отсутствию движений мыши. Реальный исход при регулярном использовании —
блокировка входа. Без риска то же делает регулярный автоперевод в приложении
банка.

## Зеркала и VPS

Кабинет раздаётся с пула доменов, `BANK_HOST=auto` подбирает живой: сначала
DNS, потом проба браузером. Именно браузером — edge банка отдаёт
`302 Security Redirect` не-браузерным клиентам и рвёт соединение, проверка
через `http.Client` привела бы к бану IP. Куки привязаны к домену: переезд на
другое зеркало = новый вход.

`RUNTIME=vps` включает экономию памяти в Chromium (один рендерер, без
расширений и фоновых сервисов); отпечаток браузера при этом не трогается.
`HEADLESS=true` антифрод замечает, поэтому на сервере правильнее headful под
`xvfb-run`, а первый вход — через VNC или копированием профиля с макбука.

Расход: браузер ~1,1 ГБ (на Linux меньше), драйвер 26 МБ, бот 13 МБ. Нужно
2 ГБ RAM — на 1 ГБ OOM-killer прибьёт Chromium вместе с сессией. Заграничный
IP почти гарантированно даёт постоянные переподтверждения входа.

## Риски

Соглашение банка, как правило, запрещает автоматизированный доступ — это ваше
решение и ваша ответственность. Антифрод может потребовать переподтверждения
или заблокировать доступ. Зеркала живут недолго.
